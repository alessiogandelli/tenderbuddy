# Bando contract — schema_version 2.0

This is the **only** document that binds `backend/` and `frontend/` together. Neither side may import code from the other: they talk only over REST and this JSON.

Rules:
- The `schema_version` field is mandatory and must be `"2.0"`.
- **Additive-only**: fields may be added, never removed or changed in meaning without bumping `schema_version`.
- Fields marked *required* must always be present. The others may be missing or `null`.
- The copies of this document inside `backend/docs/contract/` and `frontend/docs/contract/` must stay identical to this one.

```jsonc
  "source_bbox": [0.12, 0.44, 0.61, 0.47], // deprecated alias of name_bbox
  // Additive. The two regions of an LV row: the item name (Gegenstand
  // cell) and the price cell on the right (Betrag), 0..1 over the page.
  "name_bbox":  [0.12, 0.44, 0.61, 0.47],
  "price_bbox": [0.82, 0.44, 0.97, 0.47],

  "description_raw": "Zuluft - Tellerventil ... Grösse Ø 10 cm",
  "description_normalized": "Supply air valve DN100",
  "attributes": {                    // free keys, the notes are:
    "size": "DN100",                 // normalized size
    "dn": 100,
    "fire_class": "EI90",            // or null
    "manufacturer_hint": "Trox Hesco",
    "model_hint": "Z-LVS"
  },

  "quantity": 5.0,
  "unit": "pc",                      // enum §5

  "match": {                         // or null when not matched
    "product_id": "P-AIR-001",
    "install_code": "DIFFUSER",
    "confidence": 0.92,
    "price_source": "catalog"        // "catalog" | "supplier_package"
  },
  "manual_unit_price_chf": null,     // additive: estimator's all-in unit price, see §5
  "offer_price_chf": null,           // additive: printed offer total typed by hand, see §5
  "price_confirmed": false,          // additive: the estimator confirmed this price, see §5

  "status": "calculated",            // enum §5
  "flags": ["multi_variant_expanded"] // array, may be empty; enum §5

```

**Flag** = *what was not understood or is missing*. They are mandatory in the contract: a refactor may not make them disappear.

## 4. The golden math — must be reproduced **to the cent**

From `data/catalog.csv`, `data/productivity.csv`, `data/project_parameters.json`.
`waste = material_waste_pct`, `overhead = overhead_pct`, `transport = transport_equipment_pct`, `target = target_margin_pct`.

**Per Item:**
```
material_cost   = quantity × net_unit_cost × (1 + waste/100)
factor_product  = Π factor_keys, where site_efficiency applies as 1/site_efficiency
                  (all other factors multiply as they are)
adjusted_hours  = quantity × base_hours_per_unit × factor_product     # NOT rounded
labour_cost     = adjusted_hours × default_hourly_rate_chf            # uses the unrounded hours
direct_cost     = material_cost + labour_cost
```
The `adjusted_install_hours` shown in output is rounded to 2 decimals; the cost calculation uses the full value.

**Project:**
```
cost_baseline = Σ direct_cost × (1 + overhead/100) × (1 + transport/100)
indicative_selling_price = cost_baseline / (1 - target/100)      # shown, not the base of the bids
```
> **Warning:** the golden `cost_baseline` **excludes** `project_costs` (engineering, commissioning, hygiene, documentation), `small_material_pct` and `supplier_package_contingency_pct`, even though `data/README.md` includes them in the build-up. The ground truth wins. The estimator can, however, **turn on the toggle** `parameters.include_project_costs`: then `Σ project_costs` enters `direct_cost_chf` and therefore the baseline/price (the default stays off).

**Bid range** (margins `scenario_margins_pct`: 2.5 / 4.0 / 6.5):
```
reference_price = cost_baseline / (1 - target/100)
bid_price       = ceil_to( cost_baseline / (1 - margin/100), round_to_chf )   # 1000

prob_pct        = (reference_price - bid_price) / reference_price × 100
prob_raw        = clamp( reference_win_probability
                         + strategic_appetite_adjustment
                         + competition_adjustment
                         + price_sensitivity_probability_points_per_1pct_price × prob_pct,
                         minimum_probability, maximum_probability )

expected_contribution = (bid_price - cost_baseline) × prob_raw      # prob NOT rounded
estimated_win_probability (shown) = round(prob_raw, 2)
```
With the supplied parameters: `reference_win_probability = 0.55`, `strategic_appetite = +0.05`, `competition = -0.05`, `sensitivity = 0.05`, clamp `[0.05, 0.95]`, `round_to_chf = 1000`.

**Verified exactly:** LV0001 → `material 388.96`, `hours 4.35 (4.3469 full)`, `labour 417.30`, `direct 806.26`; summary → `372700.12`, baseline `414489.12`; Aggressive `426000 / 0.69 / 7986.03`.

## 5. Enums

All enum values are canonical **English**. They are the machine vocabulary shared by both sides; the client translates them into the user's language (German, French, Italian, English) at render time, keyed by these exact values. The backend never stores localized labels.

**`unit`**: `pc` | `m` | `m2` | `h` | `LS` | `system` — German documents use `Stk` → `pc`.

**`status`** (Status of an Item):
`calculated` | `supplier_quote_required` | `assumption_applied` | `review_required` | `insufficient_information` | `out_of_scope` | `non_priceable`

**`flags`** (uncertainty flags, array):
`missing_quantity` | `missing_unit` | `unclear_unit` | `no_match` | `low_confidence_match` | `multi_variant_ambiguous` | `multi_variant_expanded` | `missing_description` | `unparsed_row` | `out_of_scope` | `language_uncertain`

**`price_source`**: `catalog` | `supplier_package` | `manual` (additive: the position is priced with `manual_unit_price_chf`)

**`manual_unit_price_chf`** (additive, on an Item): an all-in direct unit cost typed by the estimator. When set (and the quantity is known) it wins over the catalogue match: `material_cost_chf = quantity × manual_unit_price_chf` (no waste), `labour_cost_chf = 0`, `price_source = manual`, status `calculated`, and the `no_match` / `low_confidence_match` flags are dropped. `null` = not set.

**`pipeline.step`**: `read` | `classify_pages` | `parse` | `overview` | `classify` | `canonicalize` | `match` | `price` | `aggregate`

**`page_types`** (additive): the outcome of the `classify_pages` step, one entry per page before any extraction. **`type`** ∈ `cover` | `index` | `captions` | `legal` | `specifications` | `modulo_offerta` | `preziario` | `lv_table` | `lv_other` | `other` (the categories mirror the analyses in `docs/tenders`). In this iteration only `lv_table` pages are read with vision and produce Items; the others are classified and ignored.

**`name_bbox` / `price_bbox`** (additive): the two regions of an LV row — the name cell (Gegenstand) and the price cell in the **rightmost column (Betrag)**, normalized 0..1. `price_bbox` is a **small, one-line-high cell** aligned with the quantity row: its `x` comes from the `Betrag` header and its `y` from the row's `Mass-Gattg./Mass-betrag` cell (never the whole column or the description's height). `source_bbox` remains a deprecated alias of `name_bbox`. They are used to draw the two rectangles in the interface and, in the future, to write the price into the PDF. Variant rows share one `name_bbox` (one description block, several measure rows); the interface draws a single name rectangle per block.

**`detections`** (additive): every row the vision engine saw (kept or discarded) with its two boxes, so detection quality is inspectable. `kept=false` + `reason` = not an Item (empty measure/price cells). `lv_id` links a kept detection to its Item.

**`pipeline.status`**: `pending` | `running` | `done` | `failed`

**`pipeline.message`** / **`pipeline.item_count`**: live progress for the processing screen. The frontend reads them while the status is `running` to show the current step and count the positions extracted so far.

**`offer_price_chf`** (additive, on an Item): the position's total **as printed in the offer** (the `Betrag` cell), typed by the estimator. It wins over every computed price and is the same in every bid scenario; the position's direct-cost share is that total at the target margin (`offer / ((1 + overhead)(1 + transport) / (1 − target margin))`), so summary, baseline and bid range stay consistent. Status `calculated`, `price_source = manual`. `null` = not set.

**`price_confirmed`** (additive, on an Item): the estimator confirmed the current price, so a price that would otherwise need a check (uncertain match, supplier quote) counts as final. Any PATCH that changes the price (`quantity`, `unit`, `product_id`, `install_code`, `manual_unit_price_chf`, `offer_price_chf`) resets it, unless the same PATCH sets it.

**`offer_prices_chf`** (additive, on a position result): what the offer prints for the position in each bid scenario, `direct_position_cost_chf × (1 + overhead) × (1 + transport) / (1 − scenario margin)`, or `offer_price_chf` for every scenario. The offer PDF export prints exactly these amounts. A tender saved before this field existed is re-priced once when it is opened.

**`offer_form`** (additive, on the Bando): the fillable blanks of the **first page classified `modulo_offerta`** (the CRB conditions form). `null` = not looked for yet (a tender read before this existed is scanned once when opened); `{"page": null, "fields": []}` = no form. Each blank is a dotted leader (`......`) in the PDF, so its box is exact: `fields[]` = `{id, page, bbox, baseline, section, row, column, kind, label, override}` with `id = "<section>.<row>.<column>"`:
- `summary` rows `chapter`, `ohne_npk`, `total` × columns `brutto`, `netto`;
- `conditions` rows `brutto`, `rabatt`, `zt1`, `skonto`, `zt2`, `bauabzuege`, `zt3`, `mwst`, `netto` × columns `eingabe` (ours), `revidiert` (the client's, left empty); plus `rabatt.pct`, `skonto.pct` (`kind = percent`).
`printed_rates` holds the rates the client printed on the form (`bauabzuege`, `mwst`, in %). `override` is a value typed by hand.

The chain (computed by the backend): Brutto = Σ of the offer amounts of the chosen positions (the same the export prints in the LV); Rabatt = Brutto × `parameters.offer_conditions.rabatt_pct` (0 by default); Zwischentotal 1 = Brutto − Rabatt; Skonto = ZT1 × `skonto_pct`; ZT2 = ZT1 − Skonto; Bauabzüge = ZT2 × printed rate; ZT3 = ZT2 − Bauabzüge; MWST = ZT3 × printed rate; Netto = ZT3 + MWST. The summary's chapter and total rows carry Brutto and Netto. A typed value replaces its field and the fields below follow it.

**`pipeline.pages_total`** / **`pipeline.pages_read`** (additive): pages of the PDF, and how many have been read and classified so far (saved mid-step, a few times per second). **`pipeline.lv_pages_total`** / **`pipeline.lv_pages_done`**: how many LV-table pages the vision engine reads, and how many it has finished (0 on the deterministic path). The processing screen fills its page tape from them.

**`overview`** (additive): a panorama of the whole document. `engine` is `luna` when a model reads it, `deterministic` when it is derived from the Items (AI off or failed). `materials_needed` and `labour_needed` are used by the user and by matching.

**`parameters`** (additive): this Bando's pricing Parameters (a copy of `project_parameters.json`, editable). They include `include_project_costs` (default `false`). `null`/missing => the dataset defaults.

**`usage`**: additive, `null` when the quote is deterministic. When AI is active it reports `calls`, `p50_ms`, `p95_ms`, `errors`, `retries`, `escalation_calls`, `input_tokens`, `output_tokens`, `cost_usd`.

**`classification`**: `ventilation` | `hvac` | `plumbing` | `electrical` | `building` | `other`

| POST | `/api/bandi/{id}/export/pdf` | the **offer**: the tender PDF as received, with the selling price of each chosen position written in its `price_bbox` cell (right-aligned on the row's baseline). Positions without a price or a price cell are skipped. The offer form (`offer_form`) is filled with the same positions: each value covers its dotted blank. | GET | `/api/productivity` | Productivity rules | `ProductivityRule[]` |

After every write (`POST /run`, `PUT /items`, `POST /items`, `PATCH /items/{lv_id}`, `PATCH /parameters`) the backend **recomputes** `position_results`, `summary` and `recommended_bid_range` and returns the updated `Bando`. The frontend never computes the price: it displays it.

## 7. Errors

Every error response has the shape `{"error": {"code": "...", "message": "..."}}`.
Codes: `not_found` | `invalid_input` | `pipeline_failed` | `unsupported_contract_version`.
